Which file owns which job?

The wrapper adapts your existing backend for AgentCore. The agent loop and Python travel tools are shared with the original application.

02 / CODE

Local UI and AWS invocation

ui.html

Collects the goal, chooses a session ID, and renders incoming events.

serve.py

Serves the page and bridges browser requests to the AWS client on port 8001.

client.py

Signs runtime requests using boto3, parses the SSE response, and can stop a session.

invoke.py

CLI entry point using the same signed client, without the browser.

Agent execution inside AWS

entrypoint.py

The AgentCore SDK entry point. Validates input and yields safe response events.

bootstrap.py

Loads tool credentials once per execution environment, then initializes the shared loop and provider.

bedrock_provider.py

Translates history, tool schemas, and Bedrock responses to the loop’s existing Decision / ToolCall contract.

backend/loop.py

Owns the reason → tool → history loop. backend/tools/ contains the actual tool functions.

Same session ≠ conversation memory.

A live session can reuse the initialized process and provider, but every Plan creates a fresh transcript in loop.run(). This wrapper adds no durable conversation memory.

Credentials have two jobs.

Your local AWS login authenticates runtime invocation. The runtime’s IAM role authorizes Bedrock and Secrets Manager. Travel API keys come from Secrets Manager; this version needs no OpenAI key.

A new session gets fresh initialization.

The UI generates a new session ID. Initialization runs in its execution environment. Configured idle timeout: 5 minutes; maximum compute lifetime: 30 minutes. Neither value represents chat history retention.

Deploy once. Invoke many times. Trace each request.

Building the container and configuring AWS happen during deployment. Clicking Plan invokes the existing runtime.

What happens when a travel tool fails?

The loop turns a tool failure into a result in the transcript. The next model call sees that failure and can change tools or arguments. Model-call failures emit an error event and end that run. Reaching the turn limit returns a partial-plan message.

Where do the external calls execute?

The model adapter and tool functions execute inside the AgentCore session environment. The adapter calls the separate Amazon Bedrock service; travel tools call external APIs such as Geoapify, Open-Meteo, Tavily, and AviationStack. The selected US inference profile can route model calls across its supported US regions.

What does the execution instance ID prove?

It is an application-generated process marker created during initialization. It helps demonstrate process reuse while a session environment is alive. It is not an AWS microVM identifier, and this code does not manage a fleet of EC2 machines itself.
